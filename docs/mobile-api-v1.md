# Mobile Driver API Documentation (v1)

This documentation describes the secure REST API endpoints designed for the Driver Itinerary mobile application built with React Native CLI + TypeScript.

---

## Base URL & Conventions

- **Base URL:** `http://<host>:<port>/api/v1`
- **Content-Type:** `application/json`
- **Accept:** `application/json`

---

## Authentication

Authentication is handled via **Laravel Sanctum** Personal Access Tokens (Bearer tokens).

Except for `POST /api/v1/auth/login`, all endpoints require the `Authorization` header:

```http
Authorization: Bearer <your_access_token>
```

### Role Enforcement
Only users with `role = 'driver'` can authenticate and perform driver trip actions. Attempting to log into the mobile API with non-driver accounts (e.g. `operator`, `admin`) results in an HTTP `403 Forbidden` response.

---

## Status Codes

| Code | Meaning |
|---|---|
| `200 OK` | Request succeeded (data retrieved, trip ended, or idempotent match). |
| `201 Created` | Resource successfully created (e.g. trip started). |
| `401 Unauthorized` | Missing or invalid Sanctum Bearer token. |
| `403 Forbidden` | Access denied (e.g. non-driver account, accessing another driver's trip). |
| `404 Not Found` | Resource not found. |
| `409 Conflict` | Business conflict (e.g. driver already has an in-progress trip, client_id belongs to another driver). |
| `422 Unprocessable` | Validation error or domain violation (e.g. missing coordinates, unassigned vehicle). |

## Endpoints

### 1. Mobile Login
Authenticates an existing driver user and issues a Sanctum personal access token.

- **Method:** `POST`
- **Path:** `/api/v1/auth/login`
- **Auth:** Public

#### Request Body
```json
{
  "email": "driver@gama.com",
  "password": "password",
  "device_name": "Samsung Galaxy A54"
}
```

#### Response (`200 OK`)
```json
{
  "data": {
    "user": {
      "id": 2,
      "name": "Juan Dela Cruz",
      "email": "driver@gama.com",
      "role": "driver"
    },
    "token": "1|AbCdEf123456789..."
  },
  "message": "Login successful."
}
```

### 5. Start Trip
Begins a trip by recording origin coordinates, time in, and client-generated UUID.

- **Method:** `POST`
- **Path:** `/api/v1/trips`
- **Auth:** Bearer Token (`auth:sanctum`)

#### Rules
1. Authenticated user must have `role = 'driver'`.
2. Driver must have an active vehicle assignment on `trip_date` for `vehicle_id`.
3. Only **one active trip** (`IN_PROGRESS`) is allowed per driver at any time.
4. `client_id` must be a valid UUID v4 generated by the mobile client.
5. Idempotency: Retrying with the same `client_id` returns `200 OK` with the existing trip without duplicate creation.
6. Destination fields remain `null`.

#### Request Body
```json
{
  "client_id": "a3bb189e-8bf9-4888-9912-ace4e6543002",
  "vehicle_id": 10,
  "trip_date": "2026-09-15",
  "time_in": "08:00:00",
  "origin_latitude": 14.5995123,
  "origin_longitude": 120.9842221,
  "origin_accuracy": 5.2,
  "origin_address": "Port Area, Manila",
  "remarks": "Morning site run"
}
```

#### Response (`201 Created` / `200 OK` on idempotent retry)
```json
{
  "data": {
    "id": 15,
    "client_id": "a3bb189e-8bf9-4888-9912-ace4e6543002",
    "driver": {
      "id": 2,
      "name": "Juan Dela Cruz",
      "email": "driver@gama.com"
    },
    "vehicle": {
      "id": 10,
      "equipment_code": "DT-01",
      "model": "ISUZU GIGA 10W",
      "plate_number": "NBD-5421",
      "vehicle_type": "DUMP TRUCK"
    },
    "driver_vehicle_assignment_id": 1,
    "trip_date": "2026-09-15",
    "time_in": "08:00:00",
    "time_out": null,
    "origin": {
      "latitude": 14.5995123,
      "longitude": 120.9842221,
      "accuracy": 5.2,
      "address": "Port Area, Manila"
    },
    "destination": {
      "latitude": null,
      "longitude": null,
      "accuracy": null,
      "address": null
    },
    "status": "IN_PROGRESS",
    "remarks": "Morning site run",
    "created_at": "2026-09-15T08:00:00+08:00",
    "updated_at": "2026-09-15T08:00:00+08:00"
  },
  "message": "Trip started successfully."
}
```

### 6. End Trip
Completes an in-progress trip with destination coordinates and time out.

- **Method:** `PATCH`
- **Path:** `/api/v1/trips/{trip}/end`
- **Auth:** Bearer Token (`auth:sanctum`)

#### Rules
1. Only the owning driver (or administrator) can end the trip.
2. Trip status must currently be `IN_PROGRESS`.
3. `time_out`, `destination_latitude`, and `destination_longitude` are required.
4. Changes status to `COMPLETED`.

#### Request Body
```json
{
  "time_out": "09:45:00",
  "destination_latitude": 14.6507112,
  "destination_longitude": 121.0365221,
  "destination_accuracy": 4.8,
  "destination_address": "Quezon City Plant",
  "remarks": "Arrived safely and unloaded"
}
```

#### Response (`200 OK`)
```json
{
  "data": {
    "id": 15,
    "client_id": "a3bb189e-8bf9-4888-9912-ace4e6543002",
    "status": "COMPLETED",
    "time_in": "08:00:00",
    "time_out": "09:45:00",
    "destination": {
      "latitude": 14.6507112,
      "longitude": 121.0365221,
      "accuracy": 4.8,
      "address": "Quezon City Plant"
    }
  },
  "message": "Trip completed successfully."
}
```

### 7. Cancel Trip
Cancels an in-progress trip.

- **Method:** `POST`
- **Path:** `/api/v1/trips/{trip}/cancel`
- **Auth:** Bearer Token (`auth:sanctum`)

#### Rules
1. Only the owning driver (or administrator) can cancel the trip.
2. Trip status must currently be `IN_PROGRESS`.
3. Status changes to `CANCELLED`.

#### Request Body
```json
{
  "remarks": "Dispatch instructed to recall vehicle due to road closure"
}
```

#### Response (`200 OK`)
```json
{
  "data": {
    "id": 15,
    "status": "CANCELLED",
    "remarks": "Dispatch instructed to recall vehicle due to road closure"
  },
  "message": "Trip cancelled successfully."
}
```

### 8. Trip History
Lists trips for the authenticated driver with pagination and filtering.

- **Method:** `GET`
- **Path:** `/api/v1/trips`
- **Auth:** Bearer Token (`auth:sanctum`)

#### Query Parameters
- `date`: Filter by exact date (`YYYY-MM-DD`).
- `date_from`: Filter trips on or after date.
- `date_to`: Filter trips on or before date.
- `status`: Filter by `IN_PROGRESS`, `COMPLETED`, or `CANCELLED`.
- `per_page`: Number of results per page (default: 15, max: 100).

#### Response (`200 OK`)
```json
{
  "data": [
    {
      "id": 15,
      "client_id": "a3bb189e-8bf9-4888-9912-ace4e6543002",
      "trip_date": "2026-09-15",
      "status": "COMPLETED",
      "time_in": "08:00:00",
      "time_out": "09:45:00"
    }
  ],
  "links": { ... },
  "meta": { ... }
}
```

### 9. Single Trip
Retrieves full details of a specific trip.

- **Method:** `GET`
- **Path:** `/api/v1/trips/{trip}`
- **Auth:** Bearer Token (`auth:sanctum`)

```json
    "origin": { ... },
    "destination": { ... },
    "status": "COMPLETED"
  }
}
```

### 10. Offline Batch Sync
Uploads locally stored SQLite trips collected while the mobile device was offline.

- **Method:** `POST`
- **Path:** `/api/v1/sync`
- **Auth:** Bearer Token (`auth:sanctum`)

#### Behavior & Idempotency
- Each trip is wrapped in its own database transaction.
- If `client_id` exists:
  - If existing trip is `IN_PROGRESS` and incoming data has destination fields, it completes the trip.
  - If existing trip is already completed, it returns the existing record without duplicate creation.
- If `client_id` is new:
  - If incoming item has destination data, it creates and immediately completes the trip.
  - If incoming item only has origin data, it creates an `IN_PROGRESS` trip.
- If one item fails (e.g. invalid coordinates or unassigned vehicle), it is reported in `errors` while valid items succeed.

#### Request Body
```json
{
  "trips": [
    {
      "client_id": "b4bb289e-8bf9-4888-9912-ace4e6543003",
      "vehicle_id": 10,
      "trip_date": "2026-09-15",
      "time_in": "07:15:00",
      "time_out": "08:45:00",
      "origin_latitude": 14.5995,
      "origin_longitude": 120.9842,
      "destination_latitude": 14.5547,
      "destination_longitude": 121.0244,
      "remarks": "Offline sync run"
    },
    {
      "client_id": "c5bb389e-8bf9-4888-9912-ace4e6543004",
      "vehicle_id": 10,
      "trip_date": "2026-09-15",
      "time_in": "09:00:00",
      "origin_latitude": 14.5547,
      "origin_longitude": 121.0244
    }
  ]
}
```

#### Response (`200 OK`)
```json
{
  "data": {
    "processed": 2,
    "failed": 0,
    "results": [
      {
        "client_id": "b4bb289e-8bf9-4888-9912-ace4e6543003",
        "status": "created_and_completed",
        "trip": { ... }
      },
      {
        "client_id": "c5bb389e-8bf9-4888-9912-ace4e6543004",
        "status": "created",
        "trip": { ... }
      }
    ],
    "errors": []
  },
  "message": "Sync completed successfully."
}
```
